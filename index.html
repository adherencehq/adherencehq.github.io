The problem

Compliance teams write the policies. Engineers write the code that is supposed to follow them. During an audit, someone has to find an example in the code for each requirement and document it with screenshots and notes. This takes weeks.

When the policy or the code changes after the audit, that documentation is out of date, and nobody is told.

How it works

Adherence matches each requirement in your policies to the code that implements it. Your team reviews the matches, and you export a signed evidence pack for your auditors.

Upload your policies

Adherence splits each document into individual requirements. When you upload a new version, it shows what changed.

Connect your code

An engineer installs our GitHub app and adds one file to your repository. The analysis runs in your own build system.

Review the matches

For each requirement, Adherence shows the code that implements it and whether it meets the requirement. A reviewer confirms or rejects each match.

Sign and export

The person responsible signs off. The evidence pack lists every requirement, its status, who reviewed and signed it, and links to the code.

Details

  • A person reviews every result. Nothing goes into the evidence pack until someone confirms it, including requirements with no matching code.
  • The pack shows gaps. It lists requirements with no matching code, and policy statements we skipped because they don't require anything, such as "the company may..."
  • Changes trigger a new review. If the code or the policy behind a confirmed match changes, the match goes back to the review queue.
  • Records can't be edited. Every review, correction and signature is kept as it happened.
  • We don't store your code. Adherence reads code when it needs to and then discards it. The evidence pack links to your code instead of copying it.

Who it's for

Compliance teams at payment companies. We're starting with the requirements for onboarding and verifying business customers.
